# 超星图书馆座位预约：Windows 本地版

静音舱功能见 [静音舱预约说明](POD_README.md)：支持单人舱和 1、6 号多人舱的手动预约、资料保存及每天 22:00 预约次日。多人舱使用现有两个账号组队，每段 90 分钟；单人舱每段 1 小时。

本目录基于 [bear-zd/ChaoXingReserveSeat](https://github.com/bear-zd/ChaoXingReserveSeat)，增加了桌面界面、区域和空座查询、最长 4 小时的分段预约，以及 Windows 定时任务管理。以下步骤适用于**包含 `desktop_gui.py`、`reserve_segments.py` 和 `schedule_task.ps1` 等新增文件的本地版本**；直接克隆上游仓库不会得到这些新增文件。文末保留上游原始说明供参考，当前界面和定时任务以本节为准。

程序使用学习通账号操作座位预约。预约结果、签到和违约规则以学校的学习通页面为准。不同学校的预约入口可能不同；目前不能保证只凭任意学校的账号密码就能列出其全部区域。

如果需要单 EXE Windows 软件包，先完成下面的首次部署，再运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-package.ps1`。脚本会在 `dist` 生成一个 ZIP，内含 `SeatDesk.exe`、定时任务脚本和空白配置；详细用法见 [PACKAGE_README.md](PACKAGE_README.md)。打包产物和本机账号配置不会上传到 Git。

## 1. 首次部署

准备 Windows 电脑、Python、学习通账号和本校任意一个区域的选座链接。当前本地环境使用 Python 3.14.5；Python 需包含 `tkinter`。如果换电脑，请复制**这个本地版本的完整项目目录**，不要直接复制旧电脑的 `.venv`。

**推荐：双击 `deploy.cmd`。**它会在项目目录创建 `.venv`、安装缺少的 Python 依赖、仅在 `config.local.json` 不存在时复制配置模板，然后打开预约界面。重复运行不会覆盖已有账号配置。安装依赖需要联网；部署脚本不会提交座位预约，也不会上传仓库。首次进入界面后仍需填写自己的学习通账号和学校选座链接；定时任务要在“定时预约”页点击“保存定时预约”后才会创建。

如果双击失败，可在 PowerShell 中手动部署并查看错误：

在 PowerShell 中进入项目目录，安装依赖：

```powershell
Set-Location 'C:\Users\30408\ChaoXingReserveSeat'  # 换电脑时改为实际路径
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install requests cryptography numpy opencv-python
if (-not (Test-Path .\config.local.json)) { Copy-Item .\config.json .\config.local.json }
```

`config.local.json` 是本机配置，已被 Git 忽略。它会以明文保存学习通密码，**不要上传或分享**。复制出的 `config.json` 是空白模板；首次打开界面后填写账号、密码和学校选座链接即可继续。

### 从手机学习通获取选座链接

这里需要的是**图书馆座位预约里的“选座”页面链接**，不是课程或学校首页链接。获取时只选本校任意一个阅览区，不需要逐个区域复制。

1. 手机登录学习通，确认已切换或绑定到要预约的学校。
2. 从学校在学习通提供的“图书馆座位预约”入口进入，选择预约日期，直到看到阅览区列表以及每个区域的“选座”按钮。不同学校的入口名称和位置可能不同。
3. 先正常点进任意区域的“选座”页，查看右上角“⋯”或“三条杠”菜单；如果有“复制链接”，直接复制并粘贴到手机备忘录核对。
4. **如果正常页面没有“复制链接”：**返回阅览区列表，暂时同时关闭手机 Wi-Fi 和移动数据，再点该区域的“选座”。页面加载失败后，打开右上角“⋯”或“三条杠”，点“复制链接”。复制完成后恢复网络。这个方法是为了让学习通显示目标页面的地址，不会提交座位预约。
5. 把链接粘贴到手机备忘录或发给自己的电脑，再检查是否包含 `deptIdEnc=`。在程序的“学校选座链接或 `deptIdEnc`”输入框粘贴**完整链接**，然后点“刷新区域”。

链接格式示例：

```text
https://office.chaoxing.com/front/apps/seat/select?deptIdEnc=0123456789abcdef&id=12345&day=2026-10-20
```

检查时主要看这两项：`deptIdEnc=0123456789abcdef` 是学校座位预约入口的标识，界面用它读取区域列表；`id=12345` 是你点开的那个区域的 `roomid`。上面的值仅为格式示例。`day`、`backLevel`、`pageToken` 等参数可能出现或变化；本程序加载区域时只需 `deptIdEnc`，所以也可以只把这 16 位字符填入输入框。

如果复制出的链接**只有 `id=`，没有 `deptIdEnc=`**，它不足以让当前界面读取该校全部区域。请回到座位预约入口，尝试复制包含 `deptIdEnc` 的选座链接；仍找不到时，先不要猜测学校标识。若菜单没有“复制链接”，可查看页面的“分享”菜单是否能复制网页地址，或向学校图书馆询问该座位预约入口。不要把学习通密码、Cookie 或带个人令牌的完整链接公开发布。

启动方式：双击 `launch_gui.cmd`，或在 PowerShell 中运行以下命令。命令行方式可以看到启动错误。

```powershell
.\.venv\Scripts\python.exe .\desktop_gui.py
```

## 2. 账号与区域

桌面软件支持添加多个本机账号。点击“添加账号”，使用“当前账号”下拉框切换；每个账号分别保存密码、学校链接、执行时间、执行星期、节假日与调休日决定，以及定时预约方案。账号 1 使用 `ChaoXingReserveSeat`，账号 N 使用 `ChaoXingReserveSeat-N`；每个任务只运行对应账号。新账号只有保存定时预约后才会创建任务，日志分别为 `last-run.log` 和 `last-run-N.log`。

1. 在界面顶部填写学习通账号、密码；密码默认遮挡。
2. 在“学校选座链接或 `deptIdEnc`”输入框粘贴完整链接，或填写其中的 16 位 `deptIdEnc`。
3. 点击“保存账号”，再点“刷新区域”。区域下拉框会显示当前账号在该学校接口中可见的区域与 `roomid`。
4. 换学校或账号时，更换对应的选座链接并刷新区域。程序会清空旧账号的区域选择。

保存账号会更新 `config.local.json`；Windows 定时任务也读取该文件。切换账号后，还应在“定时预约”标签页重新确认区域、座位与时段。

## 3. 手动查询与预约

1. 在“手动查询与预约”标签页选择阅览区。
2. 通过“年 / 月 / 日”下拉框选择日期，或点击“今天”“明天”。
3. 通过“时 / 分”下拉框选择开始和结束时间，点击“查询可预约座位”。结果是**整个所选时段**可用的座位。
4. 选中座位，点击“预约选中座位”。程序会重新核对空座，再提交预约；当前手动提交仅支持今天或明天。
5. 查看逐段结果，并到学习通“我的预约”核对记录及签到要求。

单次提交超过 4 小时曾被学校接口拒绝。程序会自动拆分长时段，例如 `11:00–21:00` 拆成 `11:00–15:00`、`15:00–19:00`、`19:00–21:00`。各段独立返回，可能部分成功；查询后座位状态也可能变化。

在“我的预约”标签页点击“刷新预约记录”，可查看当前及未来尚未结束的预约，只显示日期、时段、座位和状态。选中“待履约”记录并点击“取消选中预约”可取消该条记录；程序会在提交前重新核对状态，并在提交后刷新列表。历史记录和最终结果以学习通为准。

## 4. 定时预约

1. 先保存账号和学校选座链接，并刷新区域。
2. 打开“定时预约”标签页，选择**执行时间**和执行星期、阅览区、座位号，以及**次日**预约时段；周末闭馆时间不同时，用“按星期设置时段”按预约日的星期分别指定。
3. 点击“保存定时预约”。程序会保存当前账号的配置，并创建或更新该账号的每周任务：账号 1 为 `ChaoXingReserveSeat`，账号 N 为 `ChaoXingReserveSeat-N`。
4. 点击“刷新任务状态”查看当前账号任务的下一次执行、上次执行和结果；点击“查看运行日志”查看当前账号的日志。

可点击“备选方案”按顺序添加多个区域、座位和次日时段组合。主方案中已成功的时段会保留；备选方案只补尚未成功、且与其配置时段重合的部分，不会预约主方案目标范围外的时间。一个备选方案只补齐部分时，程序继续尝试下一方案；日志末尾的 `missing` 显示未补齐时段。在方案编辑框里点“完成编辑”会立即把备选方案写入本机配置；点主界面的“保存定时预约”时，再一并保存时段、星期与执行时间。若有未保存修改，关闭编辑框、“保存账号”、切换账号或关闭窗口前都会先提示，不再静默丢弃。`--check-only` 会列出执行计划，不会提交预约。

所选星期是**执行日**，任务预约执行日的第二天，例如周日 22:00 执行预约周一座位。电脑应在执行时间开机、保持该 Windows 用户已登录，且本机时间与学校预约时间一致。关闭界面不会删除任务。任务显示 `Ready` 只表示已就绪，**不代表预约成功**。

### 抢点加速与快速提交（`fastSprint` / `patientSubmit`）

定时任务在预约开放时刻前 5 分钟内启动时会自动等到开放时刻：开放前约 4 秒取页面令牌、前 2.5 秒取并识别滑块验证码、开放后约 0.3 秒提交；提前超过 5 分钟启动时只会在日志提示，不会提前提交。任务触发时间在保存时会自动提前 1 分钟。

账号配置里还有两个高级开关（写在 `config.local.json` 的 `reserve` 项中，一般无需修改）：

- `fastSprint: true`（账号 1、账号 2 当前均启用）：开放时刻取一次令牌后立即提交，每一段都重新取令牌、全程复用同一滑块结果，取代“开放前取令牌再提交”的预热方式（后者会因令牌过期被 302 拒绝）。学校单次预约上限为 4 小时，分段仍按 4 小时连续切分。
- `patientSubmit: true`：首轮提交最多等 12 秒回包（未启用为 8 秒），核对后的补约最多等 20 秒（未启用为 15 秒）。座位令牌页面首轮等 10 秒，补约阶段等 20 秒；核对统一等 10 秒。先让各时段获得首轮机会，再为补约提供较长等待。同一时段提交结果未知时，先核对再决定补约，不立即改用备用座位重复提交。单次提交只有在房间、座位及完整时段均匹配时才显示核对成功；其他座位的预约仅计入账号时段覆盖。

超时不再直接判失败：提交超时会标记为结果未知（账号 1 为 `outcome: unknown`），全部时段发完后按学习通真实预约记录核对一次，只对确认仍空缺的时段补提交。

### 按星期设置预约时段

同一阅览区不同日期的闭馆时间可能不同（例如 11031：周一至周五 08:30–22:00，周六、周日 09:00–21:00）。只填一个“次日预约开始/结束”时，周末晚上会提交到闭馆之后，被学校以“当前预约时段已超出可预约时间范围”直接拒绝。

在“定时预约”页点击“按星期设置时段…”，按**被预约的那一天**的星期勾选并填写时段；未勾选的星期沿用上面的统一时段。保存后写入 `config.local.json` 的 `timesByWeekday`：

```json
"time": ["10:00", "22:00"],
"timesByWeekday": {
  "Saturday": ["10:00", "21:00"],
  "Sunday": ["10:00", "21:00"]
}
```

- 键是**预约日**（通常是执行日的次日）的星期，不是执行日；例如周五 22:00 执行、预约周六，用的是 `Saturday`。
- 主方案按该日的时段拆分；备选方案仍保留自己的时段，但会被主方案的目标窗口截断，不会提交到窗口之外。
- `-CheckOnly` 输出新增 `weekday`（预约日星期），`attemptOrder` 已是截断后的实际提交顺序。

### 法定节假日不预约

任务每次执行都会先判断**要预约的那一天**（执行日的次日）是否为法定节假日。判断依据是项目目录下的 `holidays.json`；命中时任务直接跳过：不登录学习通、不提交预约，并在 `last-run.log` 写入一行原因，例如：

```json
{"date": "2026-02-17", "skipped": "statutory holiday", "holiday": "春节"}
```

“定时预约”标签页的“法定节假日不预约”勾选框对应 `config.local.json` 的 `skipHolidays`（默认开启，保存定时预约时写入）。取消勾选后，即使次日是节假日也会照常提交。

`holidays.json` 按年维护。数据可以自动获取，不必每年手工核对：

```bash
python reserve_segments.py --update-holidays              # 今年 + 明年
python reserve_segments.py --update-holidays --holiday-year 2028
```

“定时预约”标签页也有“更新节假日表”按钮：先在后台抓取，列出结果让你确认，再写入文件。数据源按顺序尝试：`timor.tech`（能区分法定节假日 / 调休休息 / 调休上班）→ `holiday-cn`（国务院通知生成的 JSON，通常在新通知发布后几天内就有）。写盘前会校验条数、年份和重复日期，任何一步失败都保持旧文件不变。

另外，每次定时运行发现**目标年份没有数据**时会自动抓取一次（失败只记一行 warning，不影响预约）。`holiday-cn` 只标注“放假/上班”，无法区分春节、清明、端午、中秋里的哪几天是法定节假日，因此这些区间先记入 `pending`：

```json
{"name": "春节", "start": "2027-02-05", "end": "2027-02-13"}
```

`pending` 区间不会自动跳过，但目标日落在其中时日志会提示 `法定节假日日期尚未确认`，界面也会显示同一提示；程序会在之后的运行里继续重试，等 `timor.tech` 补上该年份后自动转为完整数据。期间可以在“调休日决定”里逐日选择“跳过”。

手工维护仍然支持：

```json
{"name": "春节", "start": "2026-02-16", "end": "2026-02-19"}
```

- 收录的是**法律规定的节假日**（元旦 1 天、春节 4 天、清明 1 天、劳动节 2 天、端午 1 天、中秋 1 天、国庆 3 天）。只收录这些日期意味着不会误跳过普通工作日；如果希望把整个放假调休期间（例如春节 2 月 15—22 日）都跳过，按官方通知把该条目的 `start`/`end` 改成完整区间即可。
- 用 `dates` 数组也可以逐日列出：`{"name": "调休", "dates": ["2026-09-28"]}`。
- 文件缺失或格式错误不会中断预约：程序会照常提交，并在日志里提示数据文件的问题。
- 完全没有收录的年份不会跳过预约，日志会提示 `holidays.json has no 2027 entries`；点一次“更新节假日表”即可补齐。

临时想在某天强制预约，可在命令行加 `--ignore-holiday`。

### 调休日提醒（调休上班 / 调休放假）

调休日属于“非普通日”，程序**不会自动跳过**，而是列出来让你按日期决定，避免替你猜“图书馆那天开不开门”。

1. 自动更新会把调休日写入 `holidays.json` 的 `adjustments`；也可以手工补充登记，`kind` 取 `workday`（周末补班上班）或 `restday`（工作日调休放假）：

   ```json
   {"name": "春节调休上班", "start": "2026-02-14", "end": "2026-02-14", "kind": "workday"}
   ```

   也可以用 `dates` 数组逐日列出。未登记的年份不会出现任何日期，也不影响原有预约。
2. “定时预约”页的“调休日决定”会列出未来 60 天内的调休日（日期、星期、类型、当前决定）。选中一行后点“预约”“跳过”或“清除决定”，决定**立即**写入 `config.local.json`，例如：

   ```json
   "adjustments": {"2026-02-14": "reserve", "2026-02-20": "skip"}
   ```

3. 任务执行时的优先级：**按日期的决定** > 法定节假日跳过（`skipHolidays`）> 照常预约。
   - 决定为 `skip`：直接跳过，日志记录 `"skipped": "user decision"`。
   - 决定为 `reserve`：即使是法定节假日也照常提交（节假日你确认过要预约时用）。
   - 未决定：照常预约，并在 `last-run.log` 里提示 `... no decision saved, reserving by default`，界面上的“调休日决定”会显示还有几个未决定。
4. `-CheckOnly` 输出里的 `adjustment` 显示目标日期的调休类型和名称，`decision` 显示已保存的决定（未决定为 `null`）。

在项目目录的 PowerShell 中可以进行**只读检查**：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-local.ps1 -CheckOnly
Get-ScheduledTask -TaskName ChaoXingReserveSeat
Get-ScheduledTaskInfo -TaskName ChaoXingReserveSeat | Select-Object LastRunTime,NextRunTime,LastTaskResult
Get-Content .\last-run.log -Encoding UTF8 -Tail 30
```

`-CheckOnly` 只显示房间、座位和时段拆分，**不提交预约**；输出里的 `targetDate` 是要预约的日期，`weekday` 是预约日的星期，`holiday` 为空表示那天不是法定节假日，`adjustment`/`decision` 分别是该日的调休登记和已保存的决定。日志在任务实际运行后生成；文件不存在时先查看 `LastRunTime` 和 `LastTaskResult`。结果代码 `0` 表示任务进程正常结束，仍要核对各段返回及学习通记录；`267014` 表示任务被终止，不能视为预约成功。因节假日或按你的决定跳过时结果代码同样是 `0`，日志中会有 `"skipped": "statutory holiday"` 或 `"skipped": "user decision"`。

### 运行结束后自动核对预约记录

提交返回超时并不代表没约上（学校可能已经在服务端处理，只是响应没回来），所以每次定时预约结束后，程序会**再登录一次、直接读学习通自己的预约记录**，把实际结果写进该账号的日志：

```json
{"verify": "account_result", "account_index": 2, "date": "2026-11-11", "checked_at": "22:01:12",
 "target": ["11:00", "22:00"],
 "reservations": [{"time": ["11:00", "15:00"], "seat": "142", "room": "11031", "id": 199914085}],
 "missing": [["15:00", "19:00"], ["19:00", "22:00"]], "verified": "partial"}
```

- 两个账号各由自己的定时任务运行，程序用 `scheduled-run-state.json` 记录“已开始／已结束”和进程号。**所有已开始的账号都结束后**才做核对，而且**没有固定的放弃时间**：某个账号跑得慢（反复超时重试甚至几十分钟）时，先跑完的一方会一直等到它的进程真正结束；对方进程已退出（异常退出、被任务终止）则立即不再等待。由于预约耗时事先无法确定，Windows 任务的运行上限已从 10 分钟改为 30 分钟（`schedule_task.ps1`；旧任务在下次运行时会由 `run-local.ps1` 自动补到 30 分钟），核对进程最晚等到第 28 分钟（留 2 分钟给核对），确保自己还能在任务被系统终止前写完结果。
- 核对始终只针对**本进程负责的账号**：慢账号的记录由它自己的进程在结束时查，所以不会把别人“提交到一半”的状态当作结果。
- 等待超时时日志会写 `verify: wait_timeout`（含未完成的账号），随后仍会核对本账号，并注明“本次只核对了账号 N”。
- 因法定节假日、未设置星期或你的调休决定而跳过的运行不核对：没有提交过预约，日志仍只有那一行 `skipped`。
- `verified` 取值：`complete`（目标时段全部约到）、`partial`（仍有时段空缺）、`none`（该日没有查到预约）、`unavailable`（登录或查询失败）。
- 学校会把连续的预约合并成一条记录（例如 11:00–22:00），所以这里只认学校的记录，不再看逐段提交的返回值。
- 核对成功时，**日志结论和任务退出码也以核对结果为准**（`complete` → `0`，`partial`／`none` → `1`）：日志末尾会再写一条带 `"verified": true` 的最终 `status`，避免“提交全部超时、日志写失败，其实已经约上”。“查看运行日志”有核对结果时也直接显示“已全部预约／仍有时段空缺／预约失败（已核对）”，不会先报失败再报成功。核对失败（`unavailable`）不会改变退出码，只标注核对失败。
- 提交超时或座位页加载失败时，只要核对确认该时段仍未约到，程序会在服务端恢复后对每个空缺时段**再补提交一次**（日志 `progress: retry_missing`；每个时段最多一次，仍失败则交给转预约兜底）。核对不可用的补提交里，遇到“当前时间段您已有预约”会按已覆盖处理，并且同一时段不会换座位重复重试。
- 核对等待统一为 10 秒；账号级 `patientSubmit` 影响首轮提交等待（12 秒 vs 8 秒）和补约等待（20 秒 vs 15 秒），不影响核对。
- **结束弹窗直接显示查询到的预约信息**：任务结束、核对完成后，弹窗按“预约信息（学习通查询 · 日期 · 时间）”列出每条记录（时段、座位、阅览室、记录号、状态：待履约/学习中/已履约等），并给出“结论：目标时段已全部约到／仍有时段空缺／该日没有预约记录”。提交过程的超时/异常会压缩成一行统计；如果查询已确认全部约到，则只提示“提交过程中有超时，但查询已确认生效”，不再罗列每条失败。跳过的运行会注明“本次跳过，未登录查询”。
- 想手动再查一次（只读、不提交）：`.\.venv\Scripts\python.exe .\reserve_segments.py -u .\config.local.json --verify-only`，加 `--today` 查当天而不是次日。

暂停或恢复自动任务：

```powershell
Disable-ScheduledTask -TaskName ChaoXingReserveSeat
Enable-ScheduledTask -TaskName ChaoXingReserveSeat
```

### 账号2转给账号1（转预约）

仅处理本程序定时预约实际提交成功（或提交超时后核实成功）的记录。程序保存提交前快照、实际提交范围并核对最终记录，来源凭据存于 `scheduled-provenance.json`，绑定账号身份、日期、记录 ID、区域、座位和完整时段。手动预约、原有预约、历史无凭据记录，以及与手动预约合并后无法完整核对来源的记录均跳过；目标账号需要取消的冲突记录也必须有凭据，否则整次操作跳过。来源账号必须全部约满。`--check-only` 使用同样的来源检查，`--force` 不绕过此限制。凭据查询或写入失败时，无法核对的记录不参与转预约。


账号 2 的定时任务完成预约后，当晚 22:30 由独立 Windows 任务 `ChaoXingTransferSeat` 登录学习通，读取真实的预约记录，把账号 2 已约到的结果转给账号 1。“转”靠**取消再重新预约**完成，不是改签；所以最终是否成功，仍以学习通“我的预约”里的记录为准。

该功能默认关闭。在“定时预约”页勾选转预约并选择时间，再点击“保存定时预约”；这个个人设置由两个账号共用，保存在 `config.local.json` 顶层：

```json
"transferToAccount": {"enabled": true, "from": 2, "to": 1, "at": "22:30"}
```

`from`/`to` 是 1 起的账号序号，`at` 是 `HH:MM`。保存后会创建或更新 Windows 任务 `ChaoXingTransferSeat`，任务日期取账号 2 配置的执行星期；取消勾选后再保存会删除该任务。转预约时间要晚于账号 2 的执行时间（默认 22:00 之后，例如 22:30），否则账号 2 还没约完。两个账号都要有账号密码和定时预约配置，电脑在 22:30 也要保持开机。转预约结束弹窗同样会列出**账号1/账号2 当前持有的预约信息**（时段、座位、阅览室、记录号、状态）。

每次只处理**第二天需要预约的时段**：以这个时段为窗口，以学习通 `curReserves` 的真实记录为准，且只处理状态为“待履约”的记录；今天的预约、其他日期和窗口外的记录都不动。按真实记录分三种情况：

1. **账号 1 已全部约到**：只取消账号 2 在该窗口内的预约，不再重新预约。
2. **账号 1 未全部约到、账号 2 全部约到**：先取消账号 1 在该窗口内的部分记录，再对账号 2 的每条记录“取消 → 用账号 1 重新预约同一阅览区、同一座位、同一时段”（单次超过 4 小时自动拆分）。
3. **账号 1 和账号 2 都没有全部约到**：本次不操作，保持现状。

学习通是按整条预约记录取消的，所以如果一条记录跨出窗口（例如 10:00–22:00 而窗口是 11:00–22:00），程序取消后会立即把窗口外部分补回原账号，避免整条取消导致窗口外覆盖丢失。

安全回退：账号 1 的重新预约失败时，程序会立即用账号 2 把对应时段重新约回来，并在日志里记为 `restored`；即使随后查询预约记录失败，已确定失败的时段也会先约回。从取消到重新预约之间存在几十秒的窗口，座位理论上可能被他人抢走，所以转预约结束后仍要登录学习通“我的预约”核对，日志只反映程序的提交和核对结果。

运行记录写入 `last-transfer.log`，上一次的日志会归档到 `logs/last-transfer-<时间戳>.log`；界面“查看转预约日志”可以查看，真实运行结束后还会弹出标题为“超星转预约结果”的窗口。完成或部分完成都会把结果写入 `seat-transfer-state.json`；如果当天已经完整完成过，再次运行会跳过，部分完成则不会阻止手动重试。运行期间有 `seat-transfer.lock`。独立任务的运行上限为 20 分钟，执行前会等待当天已启动的账号定时任务结束（最多等到接近上限），避免读到账号 2“提交到一半”的记录；如果等待后剩余时间不足 3 分钟，本次不执行，避免任务被系统终止时座位没有归属。

也可以手动只读检查，只显示两个账号当前的预约覆盖和将要执行的动作，不取消、不提交，也不会改动 `last-transfer.log`：

```powershell
.\.venv\Scripts\python.exe .\transfer_seats.py -u .\config.local.json --check-only
```

去掉 `--check-only` 才真实执行；`--force` 忽略“当天已完成”的防重复记录，并跳过设定时间的等待；`--date YYYY-MM-DD` 指定预约日，默认明天。

## 5. 命令行操作（可选）

以下命令在项目目录中运行，把日期和 `roomid` 换成实际值。

**只查询空座，不提交：**

```powershell
.\.venv\Scripts\python.exe .\query_available_seats.py -u .\config.local.json --date 2026-10-20 --roomid 12345 --start 18:30 --end 21:00
```

在该命令末尾添加 `--reserve-seat 095` 会**真实提交今天**的指定座位；这个 CLI 选项目前只支持今天。

**只检查次日分段配置：**

```powershell
.\.venv\Scripts\python.exe .\reserve_segments.py -u .\config.local.json --check-only
```

**只核对学习通里已有的预约记录（不提交）：**

```powershell
.\.venv\Scripts\python.exe .\reserve_segments.py -u .\config.local.json --verify-only
```

加 `--today` 查当天，加 `--account 2` 只查某个账号。定时运行结束时程序会自动做同样的核对并写进日志。

**立即真实提交次日预约：**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-local.ps1
```

最后一条会提交预约并覆盖 `last-run.log`。`reserve_segments.py` 默认检查配置中的执行星期；`--ignore-weekday` 可跳过星期检查，但也会真实提交。默认还会跳过次日为法定节假日的执行；`--ignore-holiday` 可跳过这个判断（节假日也照常提交）。上游 `main.py`/`config.json` 属于原始入口；当前桌面界面和 Windows 任务使用 `config.local.json`、`run-local.ps1` 与 `reserve_segments.py`。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 双击后没有窗口 | 检查 `.venv\Scripts\pythonw.exe`；用 `.venv\Scripts\python.exe .\desktop_gui.py` 看错误。 |
| 区域为空或不是本校 | 核对账号和链接中的 `deptIdEnc`，点击“刷新区域”；不同学校接口可能不兼容。 |
| 无法保存定时预约 | 先刷新当前学校的区域并选择其座位；检查当前 Windows 用户能否创建计划任务。 |
| 查询无空座 | 核对日期、开放时间和完整时段；可换时段重新查询。 |
| 提交返回“当前预约时段已超出可预约时间范围” | 结束时间超过了该日闭馆时间；在“定时预约”页用“按星期设置时段”按预约日星期分别设置（如周六、周日 21:00 前）。 |
| 只有部分时段预约成功 | 到学习通核对各段记录，再按剩余空座调整。 |
| 任务 `Ready` 却没预约 | 查看 `Get-ScheduledTaskInfo`、`last-run.log` 和学习通“我的预约”。 |
| 日志显示 `skipped: statutory holiday` | 次日是 `holidays.json` 中的节假日，任务按设计跳过；节假日也想预约时取消“法定节假日不预约”或加 `--ignore-holiday`。 |
| 日志显示 `skipped: user decision` | 你在“调休日决定”里把该日设成了“跳过”；改成“预约”或“清除决定”即可。 |
| 调休日想提前决定 | 在 `holidays.json` 的 `adjustments` 里登记日期，再到“定时预约”页的“调休日决定”里选“预约/跳过”。 |
| 放假了却没跳过预约 | 该日期不在 `holidays.json` 中，按官方放假安排补充；日志会提示 `holidays.json has no <年份> entries`。 |
| 上次结果 `267014` | 任务被终止；检查执行时限、网络、登录过程和日志。 |
| 日志显示 `TooManyRedirects` | 登录页被反复重定向。程序现在会在开放时间后 30 秒内（最长 90 秒）换新会话自动重试；仍失败时看 `login_retry` 里的重定向链，检查代理、校园网或学习通侧状态。 |
| 验证码或接口变化 | 当前程序不保证适配所有学校及验证码类型，需核对学校实际页面和接口返回。 |

不要把 `config.local.json`、含个人预约信息的运行日志或学习通密码提交到 Git。

## 7. 最近改动

2026-11-02 起的改动摘要；逐日明细、测试与真实验证记录见 [CHANGELOG.md](CHANGELOG.md)。

### 2026-11-14 · 登录重试时限与验证

- 登录阶段按剩余时间限制 HTTP 发送和重定向，截止后不再开始新请求，换会话时关闭旧连接。运行后核对和转预约也使用登录重试，各自最多等待 30 秒。
- 208 项 Python 离线测试及 13 项 PowerShell 弹窗检查通过。账号 2 的真实登录、验证码、提交及查询链路正常；测试座位被占用，未预约成功。

### 2026-11-13 · 登录重定向循环自动重试

- 定时运行登录时遇到重定向循环（`TooManyRedirects`）、连接失败、超时或登录接口 5xx／非 JSON，会换一个全新的 HTTP session 重试到开放时间后 30 秒（最长 90 秒），不再像 2026-11-13 那样启动 5 秒就退出、错过 22:00；密码错误等确定性失败仍立即返回。
- 日志新增 `login_retry`（尝试次数、错误类型、重定向链尾部），重试耗尽时写 `login_ok: false` 再按原路径退出。

### 2026-11-12 · 以核对结论为准

- 定时运行结束后用学习通预约记录**重写最终 `status` 和进程退出码**（`complete` → 0，`partial`／`none` → 1），并在日志末尾追加一条带 `"verified": true` 的 `status`。“查看运行日志”有核对结果时直接按结论显示，不会先报失败再报成功；核对失败（`unavailable`）不改变退出码。
- 赛后核对等待统一为 10 秒（原先按账号 2 秒／10 秒）；`patientSubmit` 只影响提交等待（8 秒 vs 4 秒），不再参与核对等待。
- 核对不可用的补提交遇到“当前时间段您已有预约”（`already_held`）时计为已覆盖，并按时间段去重：同一时段不再对每个备选座位重复提交。
- 核对确认仍空缺的时段（例如座位页 10 秒超时、只提交过一次的时段），在服务端恢复后每个时段补提交一次（日志 `progress: retry_missing`）；仍失败则保持失败，交给 22:30 转预约兜底。

### 2026-11-11 · 转预约、节假日自动更新

- 新增“账号2转给账号1”的独立任务 `ChaoXingTransferSeat`（默认关闭）：读取 `curReserves` 真实记录，只处理“待履约”，按账号覆盖情况取消或“取消 → 重新预约”；失败时用账号 2 回退（`restored`），支持 `--check-only`／`--force`／`--date`、日志归档与防重复。详见上文“账号2转给账号1（转预约）”。
- 新增法定节假日自动获取：`--update-holidays [--holiday-year]` 与界面“更新节假日表”按钮，数据源 `timor.tech` → `holiday-cn`；写盘前校验年份、条数和重复日期，失败保留旧文件，写入走临时文件 + 原子替换。

- 定时任务结束弹窗、“查看运行日志”和“查看转预约日志”直接显示学习通查询到的预约信息（时段、座位、阅览室、记录号、状态）及结论。
- 新增账号级 `patientSubmit` 开关（仅账号 1 启用，见上文“抢点加速与快速提交”）。

### 2026-11-10 · 运行结束后自动核对

- 新增“运行结束后自动核对预约记录”：所有已开始的账号都结束后再登录读取 `curReserves`，把实际约到的记录和计划内空缺写进日志（`verify: account_result`），逐段提交返回值不再作为最终依据。

### 本地部署方式

#### 1、安装依赖

运行脚本前先安装一个包


如果有滑块验证，则需要额外安装numpy和opencv-python

```bash
pip install numpy, opencv-python
```

#### 2、 获取roomid（图书馆id）和seatid（座位号）

在使用之前需要先在如下获取图书馆对应的id和座位号，下面的配置里已经提供了上海大学图书馆的id。对于不知道id的，可以通过如下方式进行：

![image-20231012153826054](https://zideapicbed.oss-cn-shanghai.aliyuncs.com/img/image-20231012153826054.png)

在进入预约图书馆列表界面时断开网络，点击你想预约的图书馆的`选座`按钮，会提示网页无法打开，此时点击`右上角的三条杠`，选择`复制链接`，会得到类似这样的链接：

> https://office.chaoxing.com/front/apps/seat/select?id=5483&day=2023-10-12&backLevel=2&pageToken=0f46f3acc7be4c60862cb9815870ddfd

其中的`id=5483`的5483即为对应图书馆的id，将其填写到config.json中，座位联网后自己挑即可（详细填写参见后面的setting）

## 高级设置

在main.py中有四个参数可以选择

```python
SLEEPTIME = 0.2 # 每次抢座的间隔
ENDTIME = "07:01:00" # 根据学校的开始预约座位时间+1min即可

ENABLE_SLIDER = False # 是否有滑块验证，设置为True开启滑块验证
MAX_ATTEMPT = 4 # 最大尝试次数
```
可以直接进行修改，但是不建议把**SLEEPTIME**设置太小。

### 运行完整测试

在项目目录执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1`。测试入口与应用使用相同的运行环境：优先 `%LOCALAPPDATA%\ChaoXingReserveSeat\venv`，否则使用项目 `.venv`，依次运行全部 Python 测试和 PowerShell 弹窗测试。

Windows Task Scheduler 集成测试会创建、更新并删除一个随机命名的临时任务，不执行预约。Low Integrity 的 Python 及其子进程可能在访问 Task Scheduler 根目录时报告 `0x80070003`；应使用应用的正常运行环境执行测试，不应将此错误当作任务不存在或跳过集成测试。
